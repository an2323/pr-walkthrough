## Must-explain facts

1. **The z-index change is a real fix, not decoration.** `--zIndex-ui-library` goes
   80 → 120: from *below* `--zIndex-ui-top` (100) to *above* it, and still below
   `--zIndex-modal` (1000). A step must state both numbers and both neighbours, not
   just "the z-index increased".
2. **The actual mechanism that closes the sidebar is the REMOVED `data-prevent-outside-click`
   attribute on the menu trigger, not the new wrapper div.** `Sidebar.tsx` already has
   its own `useOutsideClick` → `closeLibrary()`. That hook skips any click landing on
   an element carrying `data-prevent-outside-click` — which the old trigger button
   had. Deleting the attribute is what makes a trigger click register as "outside the
   sidebar" and close it. A walkthrough that calls this removal "cleanup" or
   "redundant" fails this rubric outright — it is the decision, not a side effect.
3. **The `.dropdown-menu-container` wrapper solves a DIFFERENT, secondary problem:**
   once the attribute is gone, the dropdown menu's own outside-click check would also
   fire on a click on its own trigger button and close itself immediately after
   opening. The wrapper lets `DropdownMenuContent`'s callback recognise "this click
   was on my own trigger" via `closest(".dropdown-menu-container")` and skip closing.
   A walkthrough must keep these two mechanisms distinct — conflating them (as an
   earlier real Bob Shell run did) is a rubric failure.
4. **The `useOutsideClick` type widening is supporting, not a decision.** `callback:
   (event: Event) => void` → `(event: Event & { target: T })` exists only so the new
   `.contains(event.target)` check compiles; it changes no behaviour. This should be
   `minor: true` or folded into the step it supports, never its own full step.
