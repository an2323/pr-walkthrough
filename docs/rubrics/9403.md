## Must-explain facts

1. **The core reversal: which element becomes "the dragged one".** Before this PR,
   Alt-duplicating swapped the *original* element into the dragged position and left
   the *new clone* behind — i.e. the original's identity kept moving under the
   pointer, and a stationary "duplicate" was left at the start position. This PR
   flips it: the clone is what gets dragged; the original never moves. A walkthrough
   must state this swap explicitly (which element moves, which stays), not just "fixes
   duplication order".
2. **This reversal is why ~200 lines of `fixReversedBindingsForBindables` /
   `fixReversedBindingsForArrows` in `binding.ts` are deleted, not refactored.**
   Those functions existed only to repair arrow bindings *after the fact* because
   bindings pointed at the wrong element under the old swap. Once `duplicateElements`
   assigns bindings to the correct element the first time, the repair pass has
   nothing left to fix. A step should connect "we stopped swapping identities" →
   "so the binding-repair hack is now dead code" as cause and effect, not list the
   deletion as an unrelated cleanup.
3. **`pointerDownState.drag.origin` is new state, not a renamed field** — it's added
   because `dragOffset` used to be computed from the *original* element's starting
   position (which stayed put under the old scheme); with the clone now being
   dragged, the offset needs the clone's own origin instead.
4. **Two smaller, named regressions are also fixed here** and should each get at
   least a mention (they don't need full steps): (a) incorrect selection when
   duplicating labeled containers, (b) duplicating within a group but outside a frame
   should remove the duplicate from that group. Missing both entirely is a fail;
   folding them into the main step's text is acceptable.
5. **A consistent rename runs through the diff**
   (`newElements`→`duplicatedElements`, `elementsWithClones`→`elementsWithDuplicates`,
   `oldIdToDuplicatedId`→`origIdToDuplicateId`) — mechanical, must NOT get its own
   step; at most one clause noting the vocabulary shift matches the new mental model.
6. **Coverage: all logic hunks accounted for**; the 36 test/snapshot hunks
   (`classifyHunks`) should be auto-skipped, not explained.

## Trap to watch for

`actionDuplicateSelection.tsx`'s diff looks like a large rewrite (many renamed
locals, a new `getSelectionStateForElements` helper replacing inline group-selection
logic) — an analyzer that explains this file hunk-by-hunk without first understanding
fact 1 will produce a walkthrough that's technically accurate about *what* changed
per line but never says *why*, which fails the rubric even with full line coverage.
